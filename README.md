# CIPA Crop & Coord

一个面向大尺寸照片批处理的 Windows 桌面工具。界面包含三个标签：

1. **相似区域裁切**：使用 sample 图片的指定区域，在文件夹及全部子文件夹内定位相同部位并裁切。
2. **中心裁切**：按固定像素或原图比例，从每张图片的正中心裁切。
3. **坐标导出**：使用独立的 Python-compatible 模板匹配，支持“相对上一张的移动坐标”和“特征点绝对坐标”两种 CSV 输出模式。

最终发布的 `CIPA-Crop-Coord.exe` 已包含 Python 和运行库，客户电脑不需要安装 Python。

## 当前开发分支：坐标导出双模式

- 坐标导出不再复用“相似区域裁切”的识别链路，而是单独采用 `tool_9_calc_chart_center.py` 的模板匹配方法：
  1. 彩色模板和被遍历彩色图片直接参与匹配；
  2. `cv2.matchTemplate(..., cv2.TM_CCOEFF_NORMED)`；
  3. `cv2.minMaxLoc` 取得最大相似位置；
  4. 以匹配到的模板矩形中心作为特征点坐标。
- 坐标导出不使用灰度化、二值化、sample 边缘屏蔽、目标图搜索遮蔽、粗匹配/二次精修或最低相似度阈值。
- **相对移动坐标（相对上一张）**：同一文件夹第一张输出 `(0, 0)`；之后每张输出 `当前中心 - 上一张中心`。进入新的子文件夹后重新从 `(0, 0)` 开始。
- **绝对特征点坐标**：每张图片直接输出匹配中心的原始 `(x, y)` 像素位置，不减去任何基准。
- Debug 模式保存与来源 Python 类似的参考图：绿色匹配框 + 红色中心点。

> 注意：来源 `tool_9_calc_chart_center.py` 的 `calc_center_point()` 实际是“所有坐标减去该组第一张坐标”；本开发分支的第一种模式按当前需求改为“逐帧减去上一张”，因此坐标识别方法一致，但相对坐标的后处理定义不同。

## v1.1.0 更新

- 新增中文 / 日语即时切换。功能名称、按钮、提示、错误、进度日志、完成信息都会同步切换；日语模式导出的 CSV 表头为 `ファイル名,x座標,y座標`。
- 修正 `QSpinBox / QDoubleSpinBox` 增减按钮的点击区域，扩大右侧箭头可点击宽度并避免输入框 padding 覆盖按钮。
- “在图片上选择”窗口会按窗口大小自动适配整张图片，保留最大化按钮，并支持鼠标滚轮、`+ / -` 和“适应窗口”缩放。
- 已输入有效范围时，再打开图片选择窗口会自动框出当前范围。
- EXIF 快门速度优先使用 `exifread`，逻辑与 `tool_11_crop_image_forcipa.py` 保持一致；读取失败时再回退到 Pillow。
- “被遍历图片搜索范围”改为四边遮蔽百分比。默认每边 `16.67%`（旧脚本的 `1/6`），即搜索中央约 `2/3 × 2/3` 区域。
- 匹配预处理参考旧脚本：sample 二值化阈值 `190 → 255`，被遍历图片 `160 → 200`，匹配仍使用 `cv2.TM_CCOEFF_NORMED`。
- 最低相似度默认 `-1.000`，与旧脚本“始终取最大相似位置、不额外淘汰”的行为一致；需要过滤误匹配时可手动提高。
- 三种批处理均支持多线程，默认 2 线程；大尺寸图片内存占用高，不建议盲目提高。
- 新增 Debug 模式：
  - 相似区域裁切：保存 sample 二值图、每张目标图二值图和搜索遮蔽图；
  - 中心裁切：保存裁切框参考图；
  - 坐标导出：保存识别到的模板框与中心点参考图；
  - Debug 图统一缩小到最长边不超过 1600 px，并以 JPEG 70 保存，只用于识别准确度确认。
- PR 会自动运行 Windows 测试并构建 EXE，只有检查通过后再合并到 `main`。

## 功能细节

- 支持 JPG、JPEG、PNG、BMP、TIFF、WebP。
- 递归遍历指定文件夹的所有子文件夹。
- **相似区域裁切**：sample 有效范围可直接输入 `x / y / 宽 / 高`，也可点击按钮在图片预览上拖框；宽、高为 `0` 时使用整张 sample。
- **相似区域裁切**：被遍历图片搜索范围使用“四边遮蔽百分比”，也可通过代表性图片拖框后换算为四边平均遮蔽率。
- **相似区域裁切**：可另外屏蔽 sample 四周 `0%–45%`，定位时仅比较内部区域；成功后仍按完整 sample 有效范围裁切。
- **相似区域裁切**：匹配采用缩小图粗定位、原始像素精定位，并可并行处理多张图片。
- **坐标导出**：模板图片整体直接作为模板，不再提供相似区域裁切的模板范围、边缘屏蔽、搜索遮蔽和最低相似度参数。
- 图片输出名称为 `快门速度_原名`，例如 `1/100s` 的 `abc.jpg` 输出为 `1_100_abc.jpg`。
- 没有 EXIF 快门信息时使用 `unknown_` 前缀。
- 同名输出不会覆盖，自动追加 `__2`、`__3`。
- 如果输出文件夹位于输入文件夹内，输出文件夹和 Debug 文件夹会从遍历中排除。
- CSV 使用 UTF-8 BOM 编码，可直接用 Excel 打开。
  - 相对模式中文表头：`文件名,Δx（相对上一张）,Δy（相对上一张）`
  - 相对模式日文表头：`ファイル名,Δx（前画像比）,Δy（前画像比）`
  - 绝对模式中文表头：`文件名,x坐标,y坐标`
  - 绝对模式日文表头：`ファイル名,x座標,y座標`

> 坐标以读取并按 EXIF 方向处理后的图片左上角为 `(0, 0)`，x 向右、y 向下。

## Windows 客户端构建

### GitHub 自动构建（推荐）

1. Pull Request 指向 `main` 时会自动执行测试与 Windows EXE 构建。
2. 也可在 **Actions → Build Windows EXE → Run workflow** 手动构建。
3. 完成后下载 `CIPA-Crop-Coord-Windows` artifact，里面是单文件 EXE。
4. 推送 `v1.1.0` 这类 tag 也会自动构建。

### 在 Windows 本机构建

构建电脑需安装 64 位 Python 3.11，然后双击：

```text
build_windows.bat
```

结果位于：

```text
dist\CIPA-Crop-Coord.exe
```

只有构建电脑需要 Python，最终用户电脑不需要。

## 从源码运行

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

```

## 使用建议

- 坐标导出的模板图片应只包含稳定、清晰、有纹理的目标，避免大片纯色或重复图案。
- 坐标导出严格取 `TM_CCOEFF_NORMED` 的最大相似位置，不设置最低相似度淘汰，因此模板选择本身会直接影响结果。
- 相似区域裁切的默认最低相似度 `-1.000` 是为了严格复现旧脚本行为；需要过滤误匹配时可手动提高。
- 相似区域裁切的搜索遮蔽比例越大，搜索区域越小，速度通常越快，但目标如果偏离中心可能会漏检。
- 6680 万像素图片建议默认 2 线程；提高线程数前先观察内存占用。
- Debug 模式会额外写入参考图，正式大批量处理时可关闭以减少磁盘 I/O。
- 程序不会覆盖已有输出，但正式批处理前仍建议先用少量复制照片验证参数。
